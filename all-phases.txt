1. User Roles & Access Matrix
Your JWT authentication token will contain the user role. Update your routing and role-based guards according to this matrix:

Role String	Portal / UI View	Primary Capabilities
ADMIN	Super Admin Dashboard	Onboard Organizations, Onboard Standalone Clinics, Provision Org Admins & Clinic Admins, View Platform Overviews.
ORGANIZATION_ADMIN	Hospital Network Dashboard	Add Hospital Branches/Clinics, Assign Clinic Admins, View Full Hierarchy (Clinic Admins, Doctors per clinic, Clinic-wise & Network-wide Transactions).
CLINIC_ADMIN	Clinic Branch Dashboard	Onboard Clinic Doctors, Onboard Front-Desk PAs/Assistants, View Clinic Profile, Doctors, PAs, Clinic Appointments & Financial Transactions.
ASSISTANT	Front-Desk / Reception Portal	Scan Patient QR Codes, Check In Patients, View Waiting Room Queue, Front-Desk Daily Stats.
DOCTOR	Doctor Portal	View assigned patient consultations, appointment calendar, prescriptions.
USER	Patient Booking Web App	Browse doctors, book appointments, make online payments, receive QR tickets.
2. Domain-Based White-Label Resolution (Bootstrapping)
When the frontend single-page application loads, dynamically detect the host domain before rendering tenant branding.

API Call
http

GET /api/v2/partner?domain_eq={window.location.origin}
Alternative: GET /api/public/tenant?domain={window.location.origin}

Response (200 OK)

7. Booking & Payment Integration (Dynamic Razorpay)
When a patient books an appointment:

Initialize Razorpay Options: Use razorpayKeyId received from the bootstrapping API (/api/v2/partner?domain_eq=...).
Order Creation: Call POST /api/payment/create-order. The backend automatically selects the merchant credentials for the clinic/organization owning the doctor.
Payment Verification: Call POST /api/payment/verify.
json

{
  "razorpay_order_id": "order_xxx",
  "razorpay_payment_id": "pay_yyy",
  "razorpay_signature": "zzz...",
  "appointment_id": 101
}
Ticket Returned: The verification response returns the generated ticket format (HC-XXXXXXXX) and QR payload, which the patient can save or show at the front desk.
8. Error Codes & Frontend Handling
Handle these specific backend exceptions in your UI:

HTTP Status	Error Message / Code	Scenario	Recommended UI Handling
400 Bad Request	WRONG_CLINIC: Ticket belongs to clinic '...' but scanned at '...'	Patient brought their ticket to the wrong branch	Show error dialog with warning banner: "Invalid Clinic: This appointment is scheduled for [Correct Branch Name]."
400 Bad Request	ALREADY_CHECKED_IN: Checked in at ... by ...	Assistant accidentally scanned the same ticket twice	Show informational toast: "Patient is already checked in."
400 Bad Request	INVALID_STATUS: Only CONFIRMED appointments can be checked in	Appointment was cancelled or pending payment	Display modal: "Cannot check in: Appointment is cancelled or unpaid."
404 Not Found	Appointment not found for ticket: ...	Malformed or invalid QR code	Show red alert: "Invalid QR ticket code."
403 Forbidden	Access Denied	User lacks the required role for the portal	Redirect to appropriate login page.
